# Fole 开发阶段

[English](DEVELOPMENT_PHASES.md) · 相关提案：[`PROJECT_PROPOSAL_ZH.md`](PROJECT_PROPOSAL_ZH.md)

> 最初的"个人生产力审计"开发规划保存在 [docs/legacy/DEVELOPMENT_PHASES_ZH.md](legacy/DEVELOPMENT_PHASES_ZH.md)。

Fole 通过三项产品能力逐步发展：

```text
阶段 A：你去找 Fole。
阶段 B：Fole 知道什么时候该来找你。
阶段 C：Fole 能在明确授权的范围内替你行动。
```

最初的部署刻意保持很窄：一个用户、一台家里的电脑、一台学校的电脑。跨电脑的上下文融合是地基的一部分，而不是以后才补的同步功能。

## 起点情况

各阶段都建立在 FocusLedger 之上，它目前已经作为单设备节点在运行。各阶段的现状：

| 阶段 | 已经具备 | 尚未开始 |
|---|---|---|
| A — 陪伴层 | 本地配置；本地对话界面（CLI 和报告页面里的 analyst）；通过 Ollama 可插拔的本地模型；可查看的时间线；采样带 `device_id`；带版本号的本地数据库结构 | 配对与撤销、Fole Home、加密同步、跨设备共享的目标和记忆、来源与冲突处理、权限登记 |
| B — 环境智能 | 可选开启的活动和空闲感知；会重新解释历史的纠正；带阈值和冷却时间的分心提醒；通过记录工具调用和接地检查给出解释；可回放的评测（`analyst eval`） | 来自多台设备的用户层上下文、带置信度和有效期的假设、打扰预算、跨设备路由与去重 |
| C — 可信代理 | 带类型参数的只读工具：模型可以调用，但永远不能借此修改任何东西 | 任何会执行操作的工具、批准与撤销、限定范围的权限、远程批准、凭据、紧急停止 |

## 阶段 A — 陪伴层（Companion Fabric）

### 目标

在用户家里和学校的电脑之间，打造一个可用的个人助手。

### 构建内容

- Fole 的身份、配置和本地对话界面；
- 每台电脑上一个设备本地节点，支持安全配对和撤销；
- 通过用户自己掌控的 Fole Home 进行加密同步；
- 共享的目标、对话、偏好和选定的记忆；
- 事件的来源、敏感程度、保留期限和冲突处理；
- 可插拔的模型提供方、性格和提示词；
- 离线运行与延迟同步；
- 可查看的时间线和基础的权限登记。

原始的设备活动默认不同步。节点之间共享的是结构化事件或经用户批准的摘要。

### 完成标准

- 一个用户可以把家里和学校的电脑配对；
- 一段对话或一个目标可以在两台电脑之间接续；
- 共享的记录能显示来源和同步状态；
- 被撤销的设备不能再读取更新或发出指令；
- Fole Home 不可用时，助手依然可以使用。

## 阶段 B — 环境智能（Ambient Intelligence）

### 目标

让 Fole 结合有边界的设备信号，主动发起有用的交互，同时不变得吵闹或侵扰。

### 构建内容

- 可选开启的活动、在场状态、任务和设备状态传感器；
- 由多台设备的视角拼合出的用户层上下文；
- 关于进展、受阻、偏离和承诺的假设，每条都关联证据；
- 纠正、置信度、过期和隐私边界；
- 安静模式、打扰预算、冷却时间和主动程度分级；
- 跨设备通知的去重与投递路由；
- 解释 Fole 为什么介入、哪些信号起了作用；
- 用于评估不同策略的反馈与回放。

Fole 必须区分人和他的设备。同时发生的设备事件要融合在一起，而不是被当成不同的用户。

### 完成标准

- Fole 能判断哪台设备最适合进行某次交互；
- 一个事件不会在多台设备上造成重复打扰；
- 每条主动消息都能追溯到有边界的证据和策略；
- 用户可以纠正某个假设，并控制今后的行为；
- 关闭某个传感器后，它不再参与之后的任何决策。

## 阶段 C — 可信代理（Trusted Agency）

### 目标

允许 Fole 在明确且可撤销的授权范围内，跨设备协调并执行有用的操作。

### 构建内容

- 基于插件的类型化工具与连接器登记；
- 操作的预览、批准、执行、核实与撤销；
- 按操作、资源、设备、条件和时长划定范围的权限；
- 把已批准的操作路由到能执行它的节点；
- 可以远程批准，但不允许静默的远程执行；
- 幂等、重试、凭据和部分失败的处理；
- 紧急停止和立即撤销权限；
- 基于用户反馈、可查看的个性化；
- 没有副作用的回放与评估。

最初的操作应当是本地的、范围窄的、可撤销的：管理目标、记录决定、准备修改、安排提醒，或打开已批准的资源。

### 完成标准

- 没有对应的权限或批准，任何操作都不会执行；
- Fole 在执行操作的那台设备上核实结果；
- 重复的请求不会被执行两次；
- 离线、过期或被撤销的节点不能执行操作；
- 用户可以查看发生了什么、为什么、在哪里、依据的是哪项授权。

## 不变式

```text
一个用户可以有很多设备，但只有一份连贯的助手上下文。
本地原始数据不会意外变成共享数据。
没有权限，就没有操作。
权限过期或被撤销，就没有操作。
私密上下文永远不会变成无法解释的推断。
一个事件永远不会变成跨设备的重复打扰。
回放永远不会产生真实的副作用。
模型失败永远不会让确定性的安全控制失效。
```

## 研究问题

- 要有用，最少需要多少跨设备上下文？
- 相互冲突或不完整的设备信号应当如何融合？
- 某次介入应当发到哪台设备、在什么时候？
- 主动帮助在什么时候会变成打扰或监视？
- 授权如何在设备之间流转，而不变成无处不在的远程控制？
- 什么样的证据能让用户放心地再次委托同一个操作？
